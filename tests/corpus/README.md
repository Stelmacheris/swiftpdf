# Test corpus

Every file here is **original**: produced by the generator in `tools/corpus-gen` (crate `swiftpdf-corpus-gen`, MIT).
No third-party or copyrighted PDF is included. Text is made-up filler, images are computed gradients or noise,
and the external link points at `https://example.com/`. All files are released under the project license (MIT).
Output is deterministic, so regenerating gives byte-identical files.

## Regenerate

From the project root, after `. .\scripts\dev-env.ps1`:

```
cargo run -p swiftpdf-corpus-gen -- small            # rewrites tests/corpus/small/ (committed, ~0.9 MB)
cargo run -p swiftpdf-corpus-gen --release -- large  # writes the two big files to D:\dev\swiftpdf-corpus
```

Use `--out DIR` (or `SWIFTPDF_CORPUS_DIR` for `large`) to write elsewhere. Do not write large files inside the
project (OneDrive, little free space on C:). `tests/corpus/generated/` is gitignored for any other scratch output.

`cargo test -p swiftpdf-corpus-gen` checks that the committed files match the generator, that valid files parse
(with `lopdf`), that malformed files really are malformed, that the committed set is under 5 MB, and that this
README names every file.

Encrypted samples are deferred to T-037.

## Committed files (`tests/corpus/small/`)

Provenance for all: generated by `corpus-gen small`; license MIT; original content.

| File | Contents |
| --- | --- |
| one_page_text.pdf | 1 page, Helvetica text |
| hundred_pages_mixed.pdf | 100 pages cycling text, vector art (rects, curves, lines) and RGB images |
| outline_and_links.pdf | 6 pages, nested outline (5 entries), internal `/Dest` link, GoTo action, URI link, named-destination link |
| acroform.pdf | AcroForm with text, checkbox, radio group, combo box, list box |
| xfa_form.pdf | Same form plus an `/XFA` array (template and datasets streams) |
| attachments.pdf | Two embedded files (name tree) and a FileAttachment annotation |
| rotated_pages.pdf | 4 pages with `/Rotate` 0, 90, 180, 270 |
| mixed_page_sizes.pdf | Letter, A4, A3 landscape, 200x200, 2000x3000, and a page with a smaller CropBox |
| malformed_truncated_one_page.pdf | Valid 1-page file cut off before its xref and trailer |
| malformed_truncated_hundred_pages.pdf | 100-page file cut at 50% |
| malformed_xref_offsets.pdf | xref entries all point 13 bytes off |
| malformed_startxref.pdf | `startxref` points past the end of the file |
| malformed_garbage_bytes.pdf | 4,096 pseudo-random bytes |
| malformed_garbage_after_header.pdf | Valid `%PDF-1.7` header followed by random bytes |
| malformed_zero_length.pdf | Empty file |
| malformed_deep_arrays.pdf | Valid xref, but one object is an array nested 100,000 levels (stack-overflow bait) |
| malformed_deep_page_tree.pdf | Valid xref, page tree 3,000 `/Pages` levels deep above a single page |
| malformed_cyclic_page_tree.pdf | Valid xref, but the page tree root lists itself as a child |

Expected behaviour for every `malformed_*` file: the app returns an error or copes; it never panics or hangs.
The last three are structurally valid at the xref level, so a reader must defend against them while parsing
content (recursion limits, cycle detection).
